# dev: cross-project dependency automation

A `just` module (just >= 1.40, `mod?`) that lets separate repositories that
depend on each other by git pin be developed together by **file system
reference**, and moves their pins and pushes in order. Python 3 (`-I`, stdlib
only, `tomllib`), one file of logic (`dev.py`), no repository-specific names:
what is specific to a repository is its `pins.toml`, and what is specific to a
machine is the registry. Ctxloom, taskloom and Cherenkov use it; so can any
repository with Cargo git dependencies, any number of them, merged or not.

Licence: Apache-2.0 OR BSD-3-Clause, as the repository; the tool is a standalone script with no
third-party code.

## Layout

    tools/dev/
      justfile      the module: the recipes below, nothing else
      dev.py        the tool (all logic)
      VERSION       the module version; pins.toml's min_version is checked against it
      selftest.sh   builds throwaway git repositories under /home/babbitt and exercises everything
      install.sh    links the module into a repository as .dev
      README.md

## Consuming it

In the repository's `justfile`:

    mod? dev '.dev'

and `/.dev` in its `.gitignore`. `.dev` is a symlink to this directory, made by
`tools/dev/install.sh [repo]`. A link rather than a committed relative path
because the sibling's location differs per layout (a flat `../rust-support`, a
`main/` checkout, a worktree under `worktrees/`). With `mod?` a fresh clone, or
CI without the sibling, has no `dev::` recipes and the justfile still works.
Alternatives: a committed literal path (`mod? dev '../rust-support/tools/dev'`,
fine when every developer uses one layout); or vendoring: copy this directory
into the repository as `tools/dev` and `mod dev 'tools/dev'` (then the module
version is the repository's, and `VERSION` says which).

`just --list dev` lists the recipes (`just --list` shows `dev ...`).

## Recipes (names and parameters are stable)

| recipe | what it does |
|---|---|
| `dev::local [root]` | write the gitignored `.cargo/config.toml`: a `[patch."<git url>"]` per git source (Cargo.lock, Cargo.toml), every crate at its sibling checkout's **working tree** (uncommitted edits included). Cargo.toml and Cargo.lock keep the git pins. First line `# generated by just dev-local`; never overwrites a hand-written config; refuses a tracked one. |
| `dev::local-off` | remove the generated config, restore Cargo.lock from git (refuses a config it did not generate) |
| `dev::refresh [--quiet]` | regenerate when the sources or checkouts changed; silent no-op when dev-local is not enabled; fails loud when a sibling is missing (for hooks) |
| `dev::repin [--dep NAME] [--dry-run] [--no-fetch] [--no-lock]` | every pin of a registered dependency (Cargo.toml revs, `pins.toml` sites) becomes that checkout's HEAD full hash; `cargo update -p` only for crates whose pin changed |
| `dev::pins-check` | pre-commit: no `[patch]`/`[replace]`, no path dependency outside the repository, no tracked `.cargo/config.toml` with `[patch]` or generated; every git dependency a full 40-hex `rev` (no branch/tag); Cargo.lock holds each pin from git (catches a lock rewritten by the patch); `pins.toml` sites agree with Cargo.toml |
| `dev::pins-reachable [--no-fetch]` | pre-push: every pinned hash (Cargo.toml, Cargo.lock, submodule pointers) is on its dependency's remote default branch, else `push <dep> first (or run just land)` |
| `dev::land [REPO...] [--go] [--no-fetch] [--keep-going]` | push order across repositories (dependencies first) from their pins and the registry; a dry run unless `--go` |
| `dev::doctor` | report registry, siblings, git sources, submodules, what is missing; exit 1 on a problem |
| `dev::version`, `dev::selftest` | |

`just dev::local ~/workspace` keeps ctxloom's old `dev-local [root]` form.
`DEV_LOCAL_<REPO>` (the URL's last segment, upper-cased, `-` to `_`) names a
checkout, as before.

## The registry (per machine, data not code)

`~/.config/angzarr-dev/repos.toml` (`ANGZARR_DEV_REGISTRY` overrides; `--registry`).
Optional: without it, ctxloom's search heuristics apply under `root`
(`ANGZARR_DEV_ROOT`, default `~/workspace`): `<seg>`, `<seg>/main`,
`angzarr/<seg>[/main]`, `ctxloom/<seg>[/main]`, `benjaminabbitt/<seg>[/main]`, then `worktrees/<seg>--*`
(`angzarr` also `angzarr/core/main`, `core--*`). A checkout is used only if it
holds every needed crate exactly once; one at the lock's rev is preferred.

    root = "~/workspace"
    [repos.angzarr]                      # key: short name (a URL's last segment)
    path = "~/workspace/angzarr/core/main"           # string, or a list tried in order
    urls = ["github.com/angzarr-io/angzarr"]         # optional aliases (any spelling)
    default_branch = "main"                          # optional
    remote = "origin"                                # optional
    [repos]
    angzarr-build = "~/workspace/worktrees/angzarr-build--extract"   # shorthand
    "https://github.com/angzarr-io/angzarr-embedded" = "~/workspace/angzarr-merged"  # URL key

Several names or URLs may point at one path: that is how a merged repository
serves the URLs of the repositories it replaced.

## `pins.toml` (per repository, schema 1)

    schema = 1                 # must equal the module's schema; refused otherwise
    min_version = "1.0.0"      # optional: the module VERSION needed
    [[site]]                   # a pin outside Cargo.toml: constant, manifest, doc text
    dep = "angzarr-embedded"   # registry name of the dependency
    file = "crates/x/src/lib.rs"                      # path or glob
    pattern = 'ANGZARR_EMBEDDED_REV: &str = "{rev}"'  # literal text, {rev} = the 40-hex hash
    [[check]]                  # extra check `land` runs before pushing this repository
    name = "core lockstep"
    run = ["just", "check-core-lockstep"]

Patterns are matched literally around `{rev}`: never free-form rewriting.

## Hooks (lefthook snippet; never run `lefthook install` in a shared checkout)

    pre-commit:  pins-check:      run: just dev::pins-check      # glob "*.toml"
    pre-push:    pins-reachable:  run: just dev::pins-reachable
    post-checkout / post-merge: dev-refresh: run: just dev::refresh --quiet

Hooks use `just dev::...`; on a clone without the module they fail with "no
module", so guard with `just --summary | grep -q dev ||` or accept `mod?`
semantics in the hook (the snippets in the consumers do: they skip when `.dev`
is absent).

## Behaviour on failure

* `local`: a crate or checkout not found names it and the override variable and
  writes nothing; a foreign or tracked config is never touched.
* `refresh`: not enabled is silent; a changed source whose sibling is missing
  exits 1 with the message and leaves the config as it was.
* `repin`: refuses (writes nothing) when a dependency checkout is dirty,
  detached, or diverged from its remote default branch; warns when its HEAD is
  not pushed yet (normal while developing; `land` enforces order). Runs cargo
  with `CARGO_NET_GIT_FETCH_WITH_CLI=true` and `GIT_CONFIG_*`
  `url.<checkout>.insteadOf` for the repinned dependencies so unpushed commits
  resolve.
* `pins-check`: lists every finding, exit 1.
* `pins-reachable`: lists every unreachable pin, exit 1.
* `land`: stops at the first failure (dirty tree, not a fast-forward, a pin that
  is not an ancestor of the dependency's tip, a failing `[[check]]`, a refused
  push, a remote tip that is not HEAD) and prints what was landed and what was
  not reached. Pushes `HEAD:refs/heads/<default>` by remote name, hooks run, no
  `--no-verify`. Dry run prints the plan and still runs the read-only checks.

## Known limits

* While `dev::local` is on, cargo rewrites Cargo.lock (patched crates lose their
  git source): do not commit it (`pins-check` catches it); `dev::local-off`
  restores it. `--locked` builds fail under the patch.
* A crate pinned at two revs of one repository under different dependency
  names (e.g. `cli-diagnostic = { package = "angzarr-diagnostic", rev = A }`
  beside `angzarr-diagnostic` at rev B) cannot be patched to one working tree:
  cargo reports "depends on crate ... multiple times with different names".
  `dev::local` warns; repin the family onto one rev first.
* Only Cargo git dependencies are understood. The default remote branch is
  taken from the remote; branch protection / required PRs are not handled
  (`land` stops at the refused push).
